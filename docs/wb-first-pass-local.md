# Первый пробный прогон корректировки цен WB

**Текущее состояние:** расчёт и ограниченная первая партия, без
сквозного автоматического чтения карточек в облачной GitHub Actions.
Данные берутся из **свежего CSV расширения SELLER WB Auto в обычном Chrome**.
Проверку пользовательской цены на самом сайте после загрузки следует
выполнить **ещё одним запуском расширения**.

## Правила владельца

Действующая РРЦ рассчитывается через общие функции SELLER, с учётом
**акционного прайса 19.10–20.11.2026**. По окончании акции
возвращаем обычную РРЦ.

- **РРЦ выше 1 500 ₽:** идеальная цена покупателя = РРЦ × 1.05,
  без корректировки, если витринная цена в диапазоне
  РРЦ × 1.02 … РРЦ × 1.08.
- **РРЦ до 1 500 ₽ включительно:** нижняя граница остаётся РРЦ × 1.02,
  **верхняя допустимая граница = РРЦ × 1.70**.
  То есть при РРЦ 1 000 ₽ любая цена 1 020–1 700 ₽ допустима:
  автоматическое снижение не выполняется, в том числе по акционным позициям.
  Выше 1.70 — **MANUAL_REVIEW**, никакой автоматической уценки.
- Товары с РРЦ более 1 500 ₽, где наценка покупателю
  уже превышает 30%, отправляются **на ручную проверку**
  вместо безусловного снижения.
- Нет цены / РРЦ, нет наличия, уценка «УЦ», неоднозначные цены по
  размерам, скидка WB Клуба, устаревшая цена, изменение скидки —
  **пропуск**, без записи.

Пропорциональная формула для других позиций:
`цена продавца × (РРЦ × 1.05) / фактическая цена покупателя`.
Она использует **индивидуальный коэффициент** товара, а не усреднённый СПП.
На первом шаге изменение ограничено **±5% базовой цены продавца**.
Цель может быть достигнута за несколько отдельных проверенных прогонов.

## Первый запуск в Windows

Понадобятся Python 3, клон или ZIP репозитория SELLER, два свежих файла:

1. `WB_prices_*.csv`: сохранить расширением SELLER WB Auto
   **непосредственно перед проверкой**. Время считывания каждой карточки
   проверяется (по умолчанию 15 минут, максимум 30 минут).
2. `rrp.csv`: закрытый CSV-экспорт таблицы
   «База РРЦ — Mark Shmidt & JRL», Google Sheets → Файл → Скачать → CSV.
   Сама таблица нигде не публикуется.

Убедитесь, что ваши файлы лежат **локально**, не добавляйте
`rrp.csv` и `WB_prices_*.csv` в публичный GitHub репозиторий.

Запустите `scripts/wb_first_pass_windows.bat`, укажите пути к
обоим CSV. Затем выберите предварительный расчёт или первый
пробный запуск с записью. Для записи нужно вручную ввести
`ПОДТВЕРЖДАЮ` после просмотра предлагаемых артикулов.

Токен WB категории **«Цены и скидки»** вводится в консоли скрыто,
программой **не сохраняется**.

**Важно:** операция может быть выполнена только на компьютере,
где доступны актуальная выгрузка и WB Seller API. Само добавление
кода в GitHub не отправляет цены на WB.

## Что проверять после отправки

- `POST /api/v2/upload/task` лишь создаёт задание и возвращает
  идентификатор. Это ещё **не означает, что цены применены**.
- Запишите ID задания из `artifacts/wb-first-pass-report.json`,
  проверьте его состояние через `GET /api/v2/history/tasks`,
  `GET /api/v2/buffer/tasks`, детали
  `GET /api/v2/history/goods/task` и цены в карантине.
- Снимите **новый витринный CSV** после публикации изменений.
  Не отправляйте вторую корректировку тех же SKU до сверки.
- Локальная `.state/wb-first-pass-ledger.json` предотвращает
  слепое повторение одного и того же задания.
  Не удаляйте файл между циклами.

**В рабочем репозитории никакой автоматической записи на GitHub
Actions не включено**: облачная проверка покупательской цены WB
ранее получала 403/498.
