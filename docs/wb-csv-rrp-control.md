# WB: сравнение покупательской цены с РРЦ и акционным прайсом

**Режим только анализа:** `wb_agent/csv_rrp_control.py` не вызывает методы
изменения цен WB и не имеет функции записи. Принимает CSV от
`SELLER WB Auto`, где `buyer_min_rub` — минимальная видимая
незачёркнутая цена WB.

## Быстрый запуск

```powershell
py -3 -m wb_agent.csv_rrp_control "WB_prices_2026-10-20 (3).csv" --rrp-csv "rrp.csv"
```

`rrp.csv` — частный экспорт Google Sheets «База РРЦ — Mark Shmidt & JRL».
Откройте таблицу → Файл → Скачать → CSV (текущий лист).
Используются колонки «Артикул» и «РРЦ, руб.».
Поддерживаются CSV с разделителем `;` либо `,`.
Если переменная окружения `RRP_MAP_B64` задана (как в других агентах SELLER),
можно не передавать `--rrp-csv`.

Выход: `artifacts/wb-rrp-csv-control.csv` и JSON рядом.
Личные РРЦ никогда не публикуются в исходниках GitHub и не пересылаются
в дополнительный сервис.

## Как выбирается РРЦ

Для каждого WB SKU используются те же `manual_rrp`, `canonical_sku`,
`WB_RRP_ALIASES`, `box_rule`, `effective_rrp` из SELLER,
что и в существующем контроллере WB.

**19.10.2026–20.11.2026** `effective_rrp` автоматически применяет
специальные правила акционной РРЦ к участвующим артикулам Mark Shmidt,
в том числе особые округления для 8828 и MS702; обычные товары
остаются на обычной РРЦ.
Дата берётся из `checked_at` (московский часовой пояс), а
`--as-of YYYY-MM-DD` позволяет её зафиксировать явно.
После окончания акции сравнение автоматически возвращается к обычной РРЦ.

## Порог и режим рекомендаций

- `RED` — `buyer_min_rub < действующая РРЦ`: расчёт базовой цены
  пропорционально, **чтобы сначала достичь РРЦ** (как первая стадия Яндекса).
- `YELLOW` — `РРЦ <= цена < ceil(РРЦ*1.05)`: предложить
  **+3%** к цене продавца (правило Яндекса).
- `OK` — цена >= РРЦ + 5%: без изменений.
- `NO_BUYER_PRICE`, `NO_STOCK`, `NO_RRP`, `CLEARANCE`:
  без изменений; неизвестная РРЦ никогда не подменяется другой.
- `REVIEW_STEP_TOO_LARGE` — предлагаемое повышение свыше 5%
  за проход; требуется ручное согласование. Ограничение регулируется
  `--max-step-pct`.

Даже статус `PROPOSE_UPWARD_CHANGE` означает только **расчёт**,
не фактическое изменение. Это необходимая первая стадия до
подключения к официальному Seller Prices API и повторной проверки витрины.

Перед любыми будущими обновлениями потребуется заново проверить
свежесть снимка, цену продавца и отсутствие незавершённого изменения.
