# JRL — монитор цен на сторонних сайтах

Отдельный модуль в репозитории SELLER. Только чтение публичных цен; не изменяет товары.

## Запуск

GitHub → Actions → "JRL competitor price monitoring" → Run workflow.

После включения на основной ветке проверка назначена ежедневно на 09:00 МСК.
В Telegram отправляется отдельное текстовое сообщение по **каждому** сайту:
количество сопоставленных SKU, количество цен ниже РРЦ, список расхождений
со ссылками на товары. Отчёт отправляется даже при отсутствии нарушений,
а отсутствие доступа или сопоставления явно отмечается как ошибка.

## Источник цен и отправка Telegram

**РРЦ JRL не хранятся в GitHub Secrets.** За основу взята таблица Google Sheets
[«База РРЦ — Mark Shmidt & JRL»](https://docs.google.com/spreadsheets/d/1PkuleOknNhsvOX5Bmhp7ydjOnX05zuQESPcpibC-lXw/edit).
Точно 219 SKU JRL перенесены в `competitor_monitor/rrp_jrl.csv` и проверяются
по полному SHA-256 отпечатку всех пар артикул–РРЦ в
`competitor_monitor/reference_rrp.py`. При несовпадении проверка не отправляет
данные менеджерам. **Закупочные цены никогда не используются и не экспортируются.**

CSV является проверенным снимком прайса на 23.10.2026. Когда исходная таблица
РРЦ меняется, нужно обновить CSV и контрольный отпечаток, а не секрет.
Синхронизация с закрытой Google Sheet в GitHub Runner без отдельной авторизации
автоматически не выполняется.

Для уведомлений используются секреты **только Telegram**:
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

Правило: цена ниже РРЦ означает отклонение. Маркетплейсное правило «РРЦ+5%»
здесь не применяется.

В каждом Telegram-сообщении первая строка: домен — юрлицо из
`competitor_monitor/sites.json`. Следом — число проверенных товаров, число
отклонений и ссылки на конкретные карточки. Не показываются служебные строки
про тест, неполное сопоставление или внутреннюю выгрузку; такие подробности
сохраняются в JSON/CSV артефактах.

У Stylist Prof реквизиты исторические (судебный акт 2022 года), актуальность
не доказана, поэтому сообщение содержит предупреждение. На сайте IPARIKMAHER
данные страниц реквизитов и пользовательского соглашения различаются; в реестр
внесены данные страницы «Реквизиты». Два разных магазина (JRL Russia и
MWRussia) относятся к одному ООО «Фирменный Магазин».

## Расширить перечень сайтов

Файл competitor_monitor/sites.json содержит массив sites. Для нового сайта
добавить name, url, categories (пути разделов), max_product_pages. Код переписывать
не нужно, но для принципиально иной разметки могут понадобиться дополнительные
правила извлечения и тесты. Проверка ограничивает число продуктовых страниц и
использует задержку между запросами.

## Алгоритм

1. Обходит категории, находит товарные карточки и ссылки на карточки товаров.
2. Считывает актуальную цену (без зачёркнутой), цену с точкой-разделителем
   тысяч и цены в structured data Product.
3. Сопоставляет SKU по полному коду с учётом возможных кириллических букв
   в артикуле и отдельных проверенных цветовых обозначений.
4. Исключает отсутствующие товары, непроверенную цену, неоднозначные варианты,
   комплекты без отдельного утверждённого SKU. Сопоставление «похожий товар»
   за доказательство не считается.
5. Для одного SKU выбирает минимальную найденную опубликованную цену, а
   расхождения цены между страницами фиксирует отдельным признаком.
6. Сравнивает с РРЦ: любое значение ниже РРЦ — отклонение.

Все данные скачиваются после каждого запуска из Artifacts:
jrl_monitor.csv и jrl_monitor.json. Это важно для проверки полных отчётов
и для разбора невстреченных SKU.

## Ограничения и проверка достоверности

Это HTML-парсер, а не API сторонних магазинов. Антибот-защита, динамические
цены, отдельные варианты и изменение вёрстки могут мешать сбору. Если не удалось
распознать товары, скрипт обязан сообщить об этом, а не выдать «нарушений нет».
Перед использованием отчётов для претензий к контрагентам нужна выборочная
проверка карточек в браузере. Первоначальный обход четырёх сайтов уже выполнялся; после добавления ещё четырёх
покрытие необходимо проверять отдельно.

## Тесты

Python 3.12. Установить requests, beautifulsoup4 и pytest.

    python -m pytest -q tests/test_competitor_monitor.py

Для локального обхода (использует `rrp_jrl.csv`, секрет РРЦ не нужен):

    python -m competitor_monitor.monitor --no-telegram
